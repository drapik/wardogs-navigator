# Обмен конфигурациями игроков

Здесь собираются подготовленные игроками дороги, избранные маршруты, раллийные легенды и полные конфигурации карт. После проверки и слияния сопровождающим другие игроки могут скачать JSON и импортировать его в программу. Пока здесь есть только структура каталогов и порядок работы; присланных конфигураций ещё нет, и примеры или результаты автоматического распознавания не выдаются за проверенные конфигурации.

**Впервые пользуетесь GitHub? Начните с [руководства с иллюстрациями](新手投稿图文教程.md).** Есть и полная [текстовая версия](新手投稿纯文字教程.txt), которую можно открыть в Блокноте. Оба руководства пока только на китайском. Нужны лишь браузер, аккаунт GitHub и экспортированные программой файлы — устанавливать Git и писать код не требуется.

## Скачивание и импорт

1. Откройте пакет конфигурации нужной карты и сначала прочитайте его README.
2. Откройте нужный JSON и нажмите кнопку скачивания исходного файла на GitHub — или откройте Raw и сохраните как .json. В файле должен быть JSON, а не HTML-страница.
3. Через «Экспорт конфигурации» вверху программы сохраните резервную копию данных текущей карты.
4. Выберите кнопку импорта по таблице. Для сети дорог и избранного сначала переключитесь на ту же карту; полная конфигурация сама переключит на свою карту и заменит её содержимое.

| Файл | Какой кнопкой экспортируется | Как импортировать | Влияние на текущие данные |
|---|---|---|---|
| roads.json | Разметка карты → Экспорт сети дорог | Разметка карты → Импорт сети дорог | Объединяет дороги и легенды, сохраняя существующие; пункты назначения, опасные зоны и избранное не заменяются |
| routes.json | Избранные маршруты → Экспорт избранного | Избранные маршруты → Импорт избранного | Объединяет маршруты целиком и легенды; при импорте выбирается прилипание и создание общих дорог |
| project.json | Вверху → Экспорт конфигурации | Вверху → Импорт конфигурации | Заменяет полную конфигурацию карты: дороги, избранное, легенды, опасные зоны, пункты назначения и правила |

Если при импорте избранного выбрать «без повторного прилипания и без создания дорог», навигация по исходному пути работает, а недостающие дороги используются только этим избранным и в общую сеть не добавляются. Повторное прилипание считается по сети получателя, и путь может измениться. Навигация по пути по-прежнему подчиняется текущим правилам дорог и опасным зонам.

Объединение сети не перезаписывает существующие дороги принудительно; дорога с тем же ID, но другим содержимым может сохраниться как новая — после импорта проверьте дубли и параллельные участки. Для полной замены используйте полную конфигурацию, предварительно сделав резервную копию.

Экспорт сети дорог и избранного включает легенды текущей карты; полная конфигурация также содержит опасные зоны, пункты назначения и т. п. Перед публикацией проверьте, нет ли там данных, которые вы не хотите раскрывать. Локальные настройки — область захвата экрана, HUD, устройство озвучки — в эти три типа файлов не входят.

## Структура каталогов

~~~text
community/
  ozeti/
    имя_пользователя_github/
      имя_пакета/
        README.md
        roads.json       по необходимости
        routes.json      по необходимости
        project.json     по необходимости
        preview.png      необязательно, превью без личных данных
  bakurani/
  zestafona/
~~~

Пакет конфигурации содержит как минимум README.md и один JSON. Имена каталогов лучше писать строчной латиницей, цифрами и дефисами; названия и описания внутри можно писать на любом языке. Разные карты присылайте отдельно и не переносите координаты одноимённых мест между картами.

JSON берётся прямо из экспорта программы; файл можно переименовать, но не удаляйте ради публикации координаты, ID, типы участков маршрута, грубые точки, параметры прилипания и создания дорог и другие поля. Кладите конфигурацию рядом с описанием по [шаблону](SUBMISSION_TEMPLATE.md).

Программа сейчас принимает только schema=1; один JSON не должен превышать 15 000 000 байт — ориентируйтесь на ограничение импорта программы. Текущие ID карт: ozeti, bakurani, zestafona. В roads.json поле library должно быть roads, в routes.json — routes; project.json создаётся экспортом полной конфигурации.

## Публикация без программирования

1. В [репозитории проекта](https://github.com/greatredo/wardogs-navigator) нажмите Fork и создайте копию в своём аккаунте.
2. В своём форке создайте ветку от свежего main, например share-ozeti-supply-route.
3. Нажмите Add file → Create new file и укажите community/ozeti/ваше_имя/имя_пакета/README.md. Вставьте и заполните шаблон описания и закоммитьте — GitHub создаст каталоги.
4. Перейдите в созданный каталог пакета, выберите Add file → Upload files, загрузите экспортированные JSON и необязательное превью и закоммитьте в ту же ветку. Каждый JSON меньше ограничения программы в 15 МБ и ограничения загрузки через сайт в 25 МиБ. См. [справку GitHub по загрузке файлов](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).
5. Откройте Pull Request из форка: целевой репозиторий greatredo/wardogs-navigator, ветка main; источник — ваша ветка.
6. Опишите, что добавлено или исправлено, какой версией программы пользовались и какие участки проверены. Если нужны правки, продолжайте коммитить в ту же ветку — PR обновится.

По возможности в одном PR присылайте один пакет конфигурации или одно исправление для одной карты. Улучшая чужую конфигурацию, сохраните исходного автора и ссылку на оригинал и опишите свои изменения.

## Проверка и публикация

Сопровождающий проверяет формат файлов, карту, результат импорта, связи дорог, версию и описание автора, при необходимости просит дополнительную проверку в игре. С 0.5.1 программа не задаёт статус подтверждения дорог, старое поле оставлено лишь для совместимости файлов; фактический объём проверки пишется в README пакета, непроверенное достаточно честно указать. Корректный синтаксис конфигурации не гарантирует проходимость для техники.

Статичная конфигурация не гарантирует отсутствия мин или вражеских засад в текущем бою. Для опасных зон указывайте время наблюдения и область применимости и не выдавайте сведения одного боя за долгосрочный вывод о безопасности.

После слияния сопровождающий регистрирует конфигурацию в README соответствующей карты и записывает автора и фактический вклад в [список участников сообщества](CONTRIBUTORS.md). Скачивать и использовать может любой игрок; при проблемах откройте Issue с путём к конфигурации, версией программы и шагами воспроизведения.

## Авторство

Коммитом может стать и конфигурация JSON, и описание, и код — менять программу не обязательно. Автоматический учёт GitHub зависит от ветки по умолчанию, привязки почты коммита и других условий; график Contributors показывает только первые 100 человек, поэтому автор может появиться не сразу. См. [справку GitHub о Contributors](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-a-projects-contributors).

README каждой конфигурации и список участников сообщества сохраняют авторство независимо. Сопровождающий сохраняет автора коммита; при совместной работе сохраняются корректные строки Co-authored-by. Перед коммитом от чужого имени нужно узнать почту, которую автор готов использовать для коммитов, — лучше его noreply-адрес GitHub; не угадывайте и не требуйте публиковать личную почту. См. [справку о соавторах](https://docs.github.com/en/pull-requests/how-tos/commit-changes/creating-a-commit-with-multiple-authors).

Статус участника не даёт автоматически прав на слияние, выпуск или запись в репозиторий. Добавлять в Collaborator ради авторства не нужно.
